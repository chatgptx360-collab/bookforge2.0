Written for whoever (or whatever) picks this up next. It covers what the app
is, what is built, what is verified versus merely written, what is left, and
the traps that cost time during the build.

-------------------------------------------------------------------------------
1. WHAT THE APP IS
-------------------------------------------------------------------------------

A manuscript toolkit with five views, all client-routed from one Express app.
Four are reachable; the fifth is paused, not deleted:

  /converter   DOCX/PDF/EPUB/TXT/RTF conversion, multi-file, ZIP download
  /reader      A real paginated e-reader plus a section editor
  /audiobook   PAUSED. Manuscript -> chapter-by-chapter narration -> WAV/MP3
  /speech      Paste text -> speech
  /check       Finds what publishing platforms reject; fixes the mechanical ones

Audiobook Studio is hidden by AUDIOBOOK_PAUSED in src/App.tsx, which drops the
sidebar entry and the route so the view is unreachable and Vite leaves it out
of the bundle. Nothing was removed: the panel, its worker plumbing, its
autosave and its five browser tests are all still here and still type-checked.
To bring it back, set the flag false and un-skip tests/audiobook.browser.mjs.
A test in converter.browser.mjs asserts the pause holds — no sidebar entry,
and /audiobook landing on the converter rather than a blank screen.

The through-line: it must work with no API key. Conversion, the reader, the
audit and the default speech engine all run without one. Only Gemini speech and
the reader's dictionary lookup need a key.

-------------------------------------------------------------------------------

React 19 + TypeScript (strict, noUnusedLocals) + Vite 6 + Tailwind v4
Express 4, bundled by esbuild to server-build/server.cjs
Deploys to Vercel as one serverless function at /api

  server.ts                  3059 lines. Every API route + all conversion logic.
  audit.ts                    504 lines. Manuscript quality checker (pure).
  api/index.mjs              Vercel entry. Installs DOMMatrix/ImageData/Path2D
                             shims BEFORE importing the bundle — pdf-lib and
                             pdf-parse probe for them at import time.
  src/App.tsx                History-API router, 5 views
  src/components/            One panel per view

  src/components/tts/        VoicePicker, shared by both speech views
  src/utils/audio.ts         PCM helpers, WAV writer, lazy MP3, decodeWav
  src/utils/speech.ts        Engine router: local Kokoro or hosted Gemini
  src/utils/kokoro.ts        Main-thread wrapper around the worker
  src/utils/kokoro.worker.ts Worker: model load + inference (keeps UI alive)
  src/utils/kokoroVoices.ts  Voice catalogue, deliberately free of model code
  src/utils/gpu.ts           Hardware-vs-software adapter detection
  src/utils/sessionStore.ts  IndexedDB autosave for both speech views
  src/utils/readerStore.ts   Per-book position, bookmarks, highlights
  src/utils/docx.ts          Browser-side DOCX unwrapping, so size stops mattering
  src/mammoth-browser.d.ts   Types for mammoth's browser bundle (it ships none)
  src/utils/voiceBlends.ts   Two voices made by mixing Kokoro's style tensors
  tests/conversion.test.mjs  49 unit tests, node --test, against the built CJS
  tests/harness.mjs          Shared Playwright harness (server, stubs, fixtures)
  tests/*.browser.mjs        audiobook (5, skipped while paused), check (5),
                             converter (9)
  tests/kokoro.browser.mjs   Opt-in: the real model, and what it actually says
  tests/run-browser.mjs      Runs the browser suites one file at a time

Scripts:
  npm run dev     tsx server.ts  (Vite in middleware mode; use this)
  npm run build   vite build + esbuild the server
  npm start       serve the built client + API
  npm test        build:server then node --test  (49 unit tests)
  npm run test:browser  the Playwright suites, serialised (14 run, 5 skipped
                        while Audiobook Studio is paused)
  npm run test:all      both of the above
  npm run test:kokoro   loads the real voice model and checks the audio;
                        opt-in, downloads ~92 MB, takes about a minute
  npm run lint    tsc --noEmit

3. API
-------------------------------------------------------------------------------

  GET  /api/health              status, node, provider, maxUploadBytes
  POST /api/book/parse-file     -> { title, author, sections[], wordCount }

  POST /api/book/validate-epub  -> { valid, epubVersion, errors[], warnings[] }

  POST /api/book/export-docx    KDP-layout DOCX
  POST /api/book/lookup         reader dictionary (needs a key)
  GET  /api/tts/voices          hosted voice catalogue
  POST /api/tts/plan            split text into speakable chunks
  POST /api/tts/speak           raw PCM; 429 carries quotaScope + retryAfterSeconds
  POST /api/book/audit          quality findings
  POST /api/book/fix            text with exact repetition removed
  POST /api/book/revise         AI rewrite of flagged passages (needs a key)

4. WHAT IS BUILT
-------------------------------------------------------------------------------

CONVERSION
  - EPUB output is EPUB 3.0 and passes EPUBCheck 5.2.1 with 0 errors,
    0 warnings. No NCX, nav.xhtml with epub:type="toc", landmarks, stylesheet,
    mimetype stored first and uncompressed. The archive is written by a
    purpose-built ZIP writer (createZipArchive) because adm-zip cannot emit a
    stored entry, which the spec requires for mimetype.
  - Formatting survives: everything routes through a RichBlock/RichRun model,
    so bold in a DOCX is bold in the EPUB, RTF and PDF.
  - PDF input is reflowed (page markers stripped, hyphenation repaired,
    wrapped lines rejoined into paragraphs).
  - PDF output maps typographic characters to WinAnsi; non-Latin scripts are
    NOT preserved in PDF (pdf-lib standard fonts only). Use DOCX or EPUB.
  - Front matter is deduplicated: the title, a typed contents list and repeated
    chapter headings are stripped before the EPUB is written, and front matter
    without a heading becomes a "synthetic" chapter with no <h1>. This is what
    took a real manuscript from 38/100 to 88/100 on a store's check.
  - deriveTitle() will not use a first line that reads as a chapter heading or
    a named section. A manuscript opening straight on "Chapter 1: ..." has no
    title line, and taking the heading anyway printed it on the title page and
    again above chapter one — the duplication a store counts first. The file
    name is used instead.
  - DOCX never touches the upload limit. The browser runs mammoth itself and
    posts the markup as sourceHtml (src/utils/docx.ts); the server runs the
    same library over the same markup, so the result is identical. A unit test
    asserts the two paths produce deep-equal blocks. /api/book/convert,
    /parse-file, /audit and /fix all accept sourceHtml + sourceName.

READER
  - CSS multi-column pagination inside a clipping box sized to exactly one
    spread. Two pages wide, one on mobile, switchable to scrolling.
  - Four themes, four typefaces, size/spacing/margin presets, drop caps.
  - Contents with per-chapter time estimates, in-book search, bookmarks,
    four-colour highlights with notes, progress and time-left.
  - Read-aloud with sentence-level prosody planning (see reader/narrator.ts).
  - State per book in localStorage, keyed by title+author, 25 books retained.

SPEECH (two engines, switchable, choice persists in localStorage)
  - Kokoro (default): 82M-param Apache-2.0 model, runs entirely in the browser
    via transformers.js. No key, no quota, no request leaves the machine.
    28 voices, graded A..F+ from the model card, ordered best-first. Two of
    them are not Kokoro's: Sadie (244 Hz) and Cole (143 Hz) are blends built
    in src/utils/voiceBlends.ts, occupying the ids am_echo and af_river
    because the library's catalogue is frozen. Echo and River are therefore
    gone, and asking for those ids returns the blends.
  - Gemini: hosted, accepts a delivery instruction, needs a key, metered.
  - Kokoro cannot be directed, so the Delivery box is HIDDEN when it is
    selected rather than left there ignoring input.
  - Kokoro alone has a Pace slider (0.5x-2x), shown for the same reason in
    reverse: the hosted engine has no tempo control. It scales the duration
    the model predicts per phoneme, so speech gets quicker without the pitch
    rising, which resampling would do. The "of audio" estimate divides by it,
    or it would sit there contradicting the slider. Saved with the session.
  - Pace shortens the pauses along with the words, so it does not reproduce
    the wall-to-wall density of short-form narration, where the silences were
    cut in editing. That would be a trim-pauses pass on the finished audio.
  - Both resolve to raw PCM; the client stitches, writes WAV, encodes MP3
    lazily with lamejs.

AUDIOBOOK  (paused — hidden from the UI, code intact; see section 1)
  - Section checkboxes; a typed table of contents starts unticked.
    Everything/Chapters only/Nothing presets. Excluded sections are never sent.
  - Per-section redo, and retry on a failed one. Replaces audio in place.
  - Autosave to IndexedDB after every chapter. A refresh costs nothing;
    "Continue narrating" resumes.
  - Per-chapter WAV/MP3 download, or the whole book as a ZIP.

MANUSCRIPT CHECK
  - Rule-based, deterministic, no model. Same input always gives same output —
    it runs on every conversion, so it must not drift.
  - Splits findings into "fixable automatically" (exact duplicate paragraphs,
    repeated headings, typed TOC) and "needs your judgment" (repeated dialogue,
    formulaic openings, stock phrasing, thin chapters, narrow vocabulary).
  - "Fix errors" only ever DELETES. A test asserts every surviving line came
    from the original, in order. Prose is never rewritten.
  - No score is shown, deliberately: it would measure different things from the
    store's, and a green number followed by a rejection is worse than none.
  - "Revise prose" is the separate, second button, and the only path that
    changes wording. It sends each judgment-call passage to the model one at a
    time and checks every reply before accepting it: a rewrite that is empty,
    byte-identical, an apology, a note about the request, or outside
    0.55x-1.9x the original length is refused and the original kept. Nothing
    is applied until the author accepts it, and the button says plainly that
    it rewrites their words. Needs GEMINI_API_KEY; the mechanical fix does
    not.

5. VERIFIED vs NOT VERIFIED  (read this before trusting anything)
-------------------------------------------------------------------------------

VERIFIED
  - 49 unit tests and 14 browser tests pass (npm run test:all); 5 more are
    skipped while Audiobook Studio is paused. tsc --noEmit clean. Build clean.
  - THE BLENDED VOICES WORK, measured through the real UI rather than in
    Node: Sadie 243.7 Hz, Cole 142.9 Hz, against targets of 239.7 and 143.2
    taken from the reference clips.
  - THE PACE SLIDER REACHES THE MODEL. The same sentence runs 4.92s at 1x and
    3.30s at 1.5x — a ratio of 1.49 — with pitch 243.7 Hz against 245.0, so it
    is genuinely tempo and not resampling.
  - EPUB validity against real EPUBCheck 5.2.1.
  - The committed Playwright suites cover: a full narration run, autosave
    across a hard refresh, section skipping, redo, stop-is-not-failure,
    the audit, the mechanical fix, the prose revision and its guard,
    upload rejection, the advertised limit matching the enforced one,
    EPUB validity end to end, and cross-origin isolation on every view.
  - KOKORO REALLY SPEAKS. The model loads, runs and returns audio through the
    shipped code path; tests/kokoro.browser.mjs downloads the weights, drives
    the speech view and inspects the WAV that comes out — 24 kHz mono, the
    right length for the sentence, loud enough to be a voice, and with energy
    that rises and falls between syllables rather than sitting flat. Run it
    with `npm run test:kokoro`. It is opt-in because it pulls ~92 MB.
  - A 6 MB DOCX converts against a 1 MB server limit, with under 1 MB leaving
    the browser, because the client unwraps DOCX itself. A unit test asserts
    the blocks from that path are deep-equal to the blocks from the file.
  - A FULL 20-CHAPTER BOOK converts. A 20 MB illustrated manuscript (35,905
    words, a plate per chapter) went through the UI against a 4 MB server in
    10.5 seconds, posting 198 KB. All 20 chapters came out, every title
    intact, EPUB 3.0, valid, no repeated headings. A committed browser test
    holds that ground.

NOT VERIFIED — IMPORTANT
  - A WHOLE BOOK has not been narrated end to end. Single passages have, at
    both engines' hands, and a chapter is only more of the same, but a
    20-chapter run has never been watched. Moot while the studio is paused;
    the first thing to do when it comes back. See the memory note below.
  - No Gemini speech call has ever been made either. Same reason (no key in the
    build environment). The 429 handling was tested against mocked responses.
  - Long-run memory is untested. A 10-hour audiobook is roughly 1.7 GB of WAV
    held in the browser plus a copy in IndexedDB. It may be fine; nobody knows.

6. WHAT IS LEFT
-------------------------------------------------------------------------------

HIGH VALUE
  1. Do for the other input formats what is now done for DOCX: unwrap them in
     the browser so their size stops mattering. EPUB is a zip and jszip is
     already a dependency, so it is the next easy one. PDF needs pdf.js, which
     is a much larger download.
  2. A trim-pauses pass over generated audio, for short-form voiceover. The
     reference clips this was compared against are 94-96% speech because the
     silences were cut in editing; Kokoro's pace control shortens the pauses
     along with the words, so it cannot reproduce that density. Cutting
     silence from the finished PCM can.

ON HOLD WHILE AUDIOBOOK STUDIO IS PAUSED
  - Narrate a 20-chapter book and watch memory. If it fails, the fix is
    probably to drop each chapter's PCM after writing its Blob, rather than
    holding everything. Still the biggest unknown in the app.
  - One stitched audiobook file (single MP3 with chapter markers) alongside
    the per-chapter ZIP.
  - Chapter-range narration by number, not just checkboxes, for long books.

WORTH DOING
  3. A light theme for the app shell. The reader has four themes; everything
     else is dark-only.
  4. Create a main branch so work can go through pull requests. Right now the
     feature branch IS the default branch.

KNOWN LIMITS, NOT BUGS
  - Vercel rejects request bodies over ~4.5 MB at the edge. The server caps at
    4 MB when VERCEL is set and 50 MB otherwise; MAX_UPLOAD_MB overrides
    either. /api/health reports the real limit and the UI reads it from there,
    so the number a user is shown is always the number enforced.
    DOCX no longer cares: the browser runs mammoth itself and posts the
    extracted markup (src/utils/docx.ts -> the sourceHtml field), so a DOCX of
    any size converts on the deployed app. Everything else is still capped,
    and running locally is still the answer for those.
  - Vercel functions are killed at 60s. Long conversions need localhost.
  - Rate-limit state is per serverless instance, so limits are approximate.
  - PDF output cannot represent non-Latin scripts.

7. TRAPS — these cost real time, do not rediscover them
-------------------------------------------------------------------------------

  * Kokoro's generate() tokenises with truncation:true and the model caps input
    at 509 tokens. Over-long input is cut off SILENTLY — no error, just short
    audio and missing words. splitForKokoro() guarantees pieces <=320 chars and
    must never be bypassed. There is a second guard comparing audio duration to
    text length; both exist because this failure is invisible.

  * A software WebGPU adapter (SwiftShader/lavapipe) satisfies requestAdapter()
    exactly like real hardware. Accepting it is WORSE than having no GPU: it
    pulls the fp32 weights, four times the download, then runs them on a CPU
    rasterizer. src/utils/gpu.ts interrogates the adapter; do not simplify it
    back to a truthiness check.

  * Cross-origin isolation (COOP same-origin + COEP credentialless) is what
    enables SharedArrayBuffer and therefore multi-threaded WASM inference. It
    MUST be credentialless, not require-corp: the model comes from the Hugging
    Face CDN, which sends no CORP header, and require-corp blocks it outright.
    The app loads no other cross-origin resource, which is what makes site-wide
    isolation safe. Do not add a CDN font or a remote image without rechecking.

  * The dev server does NOT pick up server.ts or audit.ts changes. Restart
    `tsx server.ts` after every server edit. This was rediscovered at least
    four times; symptoms look exactly like a broken fix.

  * Anything that reads a manuscript must not treat a contents entry as a
    chapter heading. "Chapter 1: The Signal ..... 1" opens like a heading and
    is not one. isTocEntry() guards this in audit.ts.

  * Text extraction normalises single newlines to double, so a typed contents
    list arrives as one paragraph per line, not one block. Handle both shapes.

  * Stopping is not failing. The stop path throws Error('Stopped.') and callers
    match that exact string to keep finished work and suppress the error
    banner. Wrapping or rewording it silently turns "stopped" into "broken".

  * IndexedDB transactions auto-close if you await inside them. Do the get and
    the put in separate transactions.

  * Mammoth inlines every image as a base64 data URI unless told otherwise. A
    20 MB illustrated DOCX became 27 MB of HTML — bigger than the file it was
    replacing — and the request was refused. src/utils/docx.ts passes a
    convertImage that discards them. The server drops images anyway, so nothing
    is lost; remove that option and large books stop converting.

  * Playwright's setInputFiles with a large Buffer does not arrive: 20 MB as
    base64 over the debug protocol silently fails and the page never sees a
    file. Write the fixture to disk and pass the path.

  * The dev server's hot-reload socket throws "WebSocket closed without opened."
    when a suite tears down its server while a page is still handshaking. The
    browser reports it as a page error, so asserting on raw page errors turned
    it into five failures that had nothing to do with the app — every suite
    passed alone and failed in a batch. tests/harness.mjs filters Vite's
    transport and nothing else.

  * Killing stray dev servers with `pkill -f "tsx server.ts"` kills the shell
    running it, because the pattern matches its own command line. Exit code 144
    with no other explanation is this. Use pgrep to collect PIDs, then kill.

  * kokoro-js freezes its voice catalogue (Object.freeze), so a new voice id
    cannot be registered — `tts.voices.x = ...` throws "object is not
    extensible". generate_from_ids() skips the validation but wants phonemes
    the library does not export, so the way in is to serve a blended tensor
    for an id that already exists, by patching fetch in the worker. That is
    why two stock voices had to be given up rather than three added.

  * Do not trust an acoustic speaking-rate metric you have not validated
    against a known answer. Two were tried here for comparing pace. One barely
    moved while the audio genuinely sped up by 39%; the other read a 1.25x
    speed-up as slower than 1x. Generate samples at speeds you set yourself
    and check the metric recovers them before pointing it at anything real.

  * A voice can measure right and sound wrong. The first attempt at a 259 Hz
    blend hit its target within 0.1 Hz and was rejected by ear; the second
    scored better on periodicity and jitter than the voices already accepted
    and was rejected too. Pitch, clarity and jitter catch a degraded voice,
    not an unconvincing one. Ship samples and let someone listen.

  * KNOWN INTERMITTENT: "a skipped section is never sent" failed once, under
    load, reporting 1/3 sections instead of 3/3 — two chapters errored during a
    run that otherwise completed. It then passed four consecutive times alone,
    and the cause was never established. narrationSettles() now captures
    whatever error the page displayed and the assertion prints it, so the next
    occurrence says why instead of only what. If you see it, that message is
    the thread to pull.

8. HOW TO CONTINUE
-------------------------------------------------------------------------------

  git clone -b claude/bookforge-web-app-tf85x4 \
      https://github.com/chatgptx360-collab/bookforge2.0.git
  cd bookforge2.0
  npm install
  npm run dev            # http://localhost:3000

  Node 22 LTS or newer. No .env needed — Kokoro, conversion, the reader and the
  audit all work with no key. Add GEMINI_API_KEY only for hosted speech and the
  reader's lookup.

  Before any commit:  npm run lint && npm run test:all && npm run build

  Conventions worth keeping:
    - Comments explain WHY, not what. Several in this codebase record a
      specific failure; deleting them loses the reason.
    - Tests assert behaviour a user would notice, and their names read as
      claims ("the book does not open by repeating itself").
    - Never claim something works that has not been run. The Kokoro gap above
      is documented precisely because it was never verified.

  FIRST THING TO DO: run `npm run test:all`, then `npm run test:kokoro`. The
  second one downloads the voice model and proves it still speaks; if that
  passes, everything in section 6 is standing on solid ground. Five skipped
  tests are expected — that is Audiobook Studio being paused, not a failure.
